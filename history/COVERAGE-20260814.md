# Test coverage — first measurement, 2026-08-14

Line, function and branch coverage of `src/` and `external/QtMimic/src/`, measured with clang's
source-based coverage over the full test suite. This is the first time it has been measured, so this
document exists mainly to be re-run: the reproduction commands are at the end, and the tracking table
below takes one row per measurement.

## Tracking

| date | library | lines | functions | regions | branches | tests |
|---|---|---|---|---|---|---|
| 2026-08-14 | QtLikeSignal | **88.3%** | **98.6%** | 88.1% | 73.7% | 180 |
| 2026-08-14 | QtMimic | **87.7%** | 97.7% | 87.4% | 73.1% | 180 |

Both libraries run the same 180 tests and land within half a point of each other, which is itself a
check: the suites are identical, so a real gap between these two numbers would mean the libraries
have diverged somewhere the tests do not look.

**Read the two caveats below before quoting the headline.** 88% is the figure for the code that a
Linux build compiles, and line coverage is the most generous of the four columns.

## Caveat 1: Windows is not in the number at all

`EventDispatcherWin32.cpp` and `ThreadWin.cpp` are not compiled in a Linux build, so they do not
appear as 0% — they are absent from the denominator. Counting them would put the real figure nearer
80%.

That is risk R22 in `OPEN-RISKS-20260813.md`, which is open and deliberately parked: closing it needs
a real Windows message loop, which this development machine cannot provide from WSL.

## Caveat 2: branch coverage is the honest column for this library

Line coverage says a line ran. For a threading library that is a weak claim — it does not say the
interleaving that breaks the line ran. **73%** of branches is the more meaningful number, and the
uncovered third is concentrated in two places:

- **Error handling.** `pthread_create` failing, the scheduler refusing `SCHED_IDLE`, a dispatcher
  refusing an event because it is closing. These need fault injection to reach.
- **Timing paths.** The branch where a wait times out rather than being woken, and the reverse.

## Only three functions are never called

Identical in both libraries:

| function | why it matters |
|---|---|
| `CoreApplication::post()` | **Worth a test.** Public API, and one of the four statics whose thread-safety contract was rewritten on 2026-08-13 (R15). Nothing exercises it |
| `Thread::name()` | A trivial accessor over a member fixed at construction |
| the match branch of `ThreadData::removeParkedEventsFor()` | No parked event has ever belonged to a destroyed object in a test. Added with R32; the *sweep* runs, the *match* does not |

Everything else in both libraries is executed at least once. A 98.6% function rate against an 88%
line rate is the expected shape: the suite reaches nearly every function and then exercises the
common path through it.

## What would move the number

In the order that buys the most per unit of work:

1. **A test for `CoreApplication::post()`.** Public, contract recently rewritten, currently unproven.
2. **The R32 parked-event removal path** — destroy an object that has events parked on a thread that
   never started. One test, and it closes the last never-executed branch of that feature.
3. **Fault injection on the POSIX paths**, which is what stands between `ThreadPosix.cpp` and the
   rest. This is a real piece of work — it needs the syscalls behind a seam that a test can fail on
   demand — and is worth doing only if those paths are considered load-bearing.
4. **Windows.** Not a coverage exercise so much as R22.

Chasing the percentage beyond that is not obviously worth it. The uncovered remainder is mostly
"the OS said no", and a test that fakes the OS saying no proves the handler compiles more than it
proves the handler is right.

# How this was measured

Built in a scratch directory rather than through `waf`, so the project's build configuration is
untouched and the measurement can be repeated without reconfiguring anything.

```sh
GT=submodules/external/googletest/googletest
GTLIB=out/linux/Tests/linux64-clang/debug/submodules/external/libgoogle-test.a
COV=/usr/lib/llvm-22/bin        # must match the clang that built the binary

# QtLikeSignal
clang++ -std=c++17 -O1 -g -fprofile-instr-generate -fcoverage-mapping \
    -Isrc -Isrc/tests -I$GT/include \
    src/AbstractEventDispatcher.cpp src/CoreApplication.cpp src/EventDispatcherDefault.cpp \
    src/Object.cpp src/Thread.cpp src/ThreadData.cpp src/Timer.cpp \
    src/EventDispatcherLinux.cpp src/ThreadPosix.cpp \
    $(ls src/tests/*.cpp | grep -vE 'Performance|Regression|PerfAlloc') \
    $GTLIB -lpthread -o qls-cov

LLVM_PROFILE_FILE=qls.profraw ./qls-cov
$COV/llvm-profdata merge -sparse qls.profraw -o qls.profdata
$COV/llvm-cov report qls-cov -instr-profile=qls.profdata \
    -ignore-filename-regex='(tests/|googletest|/usr/)'
```

QtMimic is the same with `external/QtMimic/src/*.cpp` and `external/QtMimic/tests/*.cpp`.

Three things to get right, each of which was got wrong first:

- **`-ignore-filename-regex` is not optional.** Without it the total reads **74%**, because gtest's
  headers are counted and are mostly unused. The number is meaningless unless the filter is applied.
- **The benchmark and guard files must be excluded** from the QtLikeSignal build. They carry their
  own `main()`-adjacent machinery and a global `operator new` replacement.
- **`llvm-profdata` must match the compiler.** Version 22 here, because clang 22 built the binary; an
  older `llvm-profdata` on the PATH will refuse the profile.

The suite is run once, in declaration order. Coverage numbers do not depend on ordering, so there is
no reason to shuffle, and every test passing is a precondition — a failing run measures less code
than it appears to.
