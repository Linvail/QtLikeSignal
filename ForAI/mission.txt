* We need to build a library that mimics a part of QtCore's features.

* This mission has the following stages.
1. Support cross-thread queued signal/slot connection, e.g. QObject::connect, disconnect, etc.
We need to support very flexible connect(), i.e. the connect function templates must resolve many use cases.
For example, connect to parent class's method, connect to overloaded method, connect to a method that returns non-void
type, connect to a method that take const reference type argument while the signal takes raw type, and connect to lambda,
basic function, and functor.
I suppose that we at least need to mimic QObject, QThread.

2. Support deleteLater as Qt.

3. Support callLater(). Qt doesn't support in C++ but supports in QML.

4. Support QObject::startTimer(), killTimer(), timerEvent(), a part of features of QTimer.

4.5 Support setter/getter of priority of Thread on Windows and UNIX (pthread-backend).

5. Support QAbstractEventDispatcher, and concrete dispatcher for Windows and Linux. I want to receive OS/platform's
messages. 100% cpu-spin is not allowed.

6. Support QObject::installEventFilter, QObject::removeEventFilter().

7. Full event system, like QEvent.

2. I use Waf build system and C++17. You must avoid using C++20 unless it's very helpful.
Warn me before using any C++20 features.
This library is meant to be cross-platform. Do not use compiler-specific preprocessor, e.g. #pragma once
Do not rely on compiler-specific tolerance, i.e. MSVC accept a thing but clang does not, do not use that thing.

3. Avoid creating code/feature that is deprecated or discouraged by Qt, including Qt5, Qt6, and Qt7.
For example, in Qt6.11's online document, it states that use of QCoreApplication::processEvents() is discouraged.
Therefore, we shouldn't mimic this function.
