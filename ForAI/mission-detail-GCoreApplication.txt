* Overview
The purpose of CoreApplication is a base class of the real application class.
It will be created in the main thread and `adopt` the main thread.
The Object that lives in the main thread will have its event-loop running in the main thread.

For example:

```
class MyApplication : public CoreApplication
{
    void init();
    void deInit();
};
```

It's supposed to be created and run a loop in the main thread.
For example:

```
int main(...)
{
    MyApplication app;
    app.init();
    int ret = app.exec(); // An event loop runs here.
    app.deInit();
    return ret;
}
```


* OS/platform integration.
The CoreApplication has another important responsibility - receiving OS/platform messages/events.
One way to do it is a CoreApplication::setEventDispatcher().

On Linux Wayland/X11, it might be simpler because we can use FD.
We can use a separate thread to listen on the FD while keep the main thread wait (no CPU-spin).
If the FD hear something, we wake up the main thread and extract the messages from the FD.

On Windows, the Windows message is only sent to the thread from created the window.
So, it is tricky. We need to make the main thread wait, but our loop must be waken when our event
is incoming or the OS message is incoming.

I wonder how Qt6 implements this.

* Static help function.

** QCoreApplication::processEvents(...)
According to the Qt doc: Processes some pending events for the calling thread according to the specified flags.

This is a very important helper function, although it is directly related to QCoreApplication.
It is more like a helper function put in QCoreApplication.

It provides a way to let `adopted` thread to process the our events.
Another way is these interfaces on Thread:
```
void processEvents();

void setWakeCallback
    (
    std::function<void()> aWake
    );
```

The setWakeCallback sets a function that wakes the adopted thread when the thead got new tasks
(MetaCall, DeferredDelete, etc.).
The `adopted` thread usually has it own loop. In the loop, we must call processEvents().

```

MyObject::MyObject()
{
    thread()->setWakeCallback(
        []()
        {
            // Wake the thread by sending EVENT_TYPE_OURS.
            SendEventToThread( threadId, EVENT_TYPE_OURS );
        }
    )
}


int MyObject::mainLoop() // <-- this runs in the thread whose Id is threadId.
{
    int event = WaitForEvent(); // Blocking call, thread waits here.

    if(event & EVENT_TYPE_A) {}

    if(event & EVENT_TYPE_B) {}

    (event & EVENT_TYPE_OURS)
    {
        // With the interfaces above:
        thread()->processEvents();

        // If it is Qt6, it should look like:
        QCoreApplication::processEvents();
    }
}

```
